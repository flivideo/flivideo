Snappy: a tripod for your screen, with a send button

You already have the idea: ScreenTour locks a region and snaps it again and again. What is missing is a native shell: keyboard cycling across regions, a visible outline, and a hand-off to B-Roll Pilot. No library of its own.

The spec

What the job is

RegionNamed, grouped, scoped (global / brand / project), stored relative to a display's UUID, in points, top-left origin. ≤ 15 active.
InterfaceMenu-bar agent plus a CLI over a socket. No TUI.
CaptureScreenCaptureKit in-process (baseline: screencapture -R, measured 0.18 s). Native pixels, PNG.
ModesSingle, countdown 3/5 s, timed series, repeated same-region shots (tabs, scrolling). Multi-region is later.
SendSpool, then broll.register on FliStudio's loopback door (place: copy). Queue and retry when it is down; delete only on confirmed receipt.
Display changeMatch by UUID, then name+size, else flag the region unresolved. Never capture the wrong area.
Does notDescribe, tag, store, annotate, record video.

Done-check (for the later build)

proofCapture a region on each of the four displays, including the negative-x one; the pixel size equals the region × scale; a register call returns created: true.
outlineA shot taken with the outline on contains no yellow frame (pixel check).
offlineFliStudio stopped: shots queue, none lost; restart: all arrive once.
test_auditdev-team:audit-test-quality on the new tests

Out of scope

  • Video recording, annotation, scroll-stitching
  • Multi-region coordinated capture (dossier §15.5)
  • Following an app window
  • Windows/Linux

What I found by measuring

  • Prior art exists. ScreenTour at /Users/davidcruwys/dev/ad/apps/screentour (Python, 1,125 lines) plus the zsh sc_* functions. The Ruby screenshot gem was only a ChatGPT thread; not on disk.
  • y=0 trap. AppKit puts the origin bottom-left, screencapture -R top-left. On this Mac -R -1500,100,400,300 gave a 400×40 image, not 400×300. Regions must be stored display-relative and converted at capture time.
  • Outline can't be hidden by window flags. Reports say sharingType = .none stopped working against ScreenCaptureKit on macOS 15+. So draw it outside the rect.
  • Hotkeys: Carbon RegisterEventHotKey reportedly needs no extra permission; only Screen Recording is needed.

Choices for David

1. Language: Swift or Rust?

Rust crates (screencapturekit, global-hotkey) are current; Swift is native for the overlay and menu bar.

Swift. Three of the four hard parts are AppKit.

2. Capture engine

ScreenCaptureKit in-process, or shell out to screencapture -R.

ScreenCaptureKit, with screencapture as the baseline in spike S1.

3. Interface

Menu-bar agent + CLI, TUI, or window app.

Menu-bar agent + CLI. The TUI hid behind what it captured.

4. Hotkeys

Defaults proposed: ⌃⌥← / ⌃⌥→ cycle, ⌃⌥Space snap, ⌃⌥C countdown.

Accept as defaults, configurable, after spike S3 checks clashes.

5. Keeping the outline out of the shot

Frame outside the region, or hide it for ~50 ms while capturing.

Outside the region. No flicker, no reliance on OS flags.

6. Where regions live

One file in ~/.config/appydave, or a file per project.

One file, scope field on each region.

7. Ask B-Roll Pilot for region, group and sequence fields

Works today via tags, but that is a change to another lane's spec.

Yes, via flivideo-orch; I did not edit it.

8. File format

PNG or JPG.

PNG, native pixels.
