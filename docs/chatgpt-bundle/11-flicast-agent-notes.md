# FliCast — Agent Notes

Only what the code cannot tell you. The rules are in `../CLAUDE.md`; the narrative is `SYSTEM.md` (not loaded).

## Shapes

Every schema, type and closed set: [`schema-mirror.md`](./schema-mirror.md) (generated, never hand-edited; after a
schema change run the dev-team `schema-mirror` skill's `verify_mirror.py docs/schema-mirror.json`). Its "Cannot be
mirrored" table is real: `defineCapability(...)` results are not expanded, so a verb's params are in

`@flivideo/core`'s: cite its mirror, never restate them.

## Tooling

- `@appydave/core` is a `file:` link to `../../apps/appydave-foundation/packages/core/dist`: build that repo first
  (`bun install --frozen-lockfile && bun run build`). Unbuilt, typecheck and main-process tests fail; the build passes.
- After `npm install`, if `node_modules/electron/dist` is empty run `node node_modules/electron/install.js`.
- `npm run build` is part of every gate: some failures exist only in the bundled main process (a CommonJS default
  import — resolve `mod.compare ? mod : mod.default` once). Golden-frame tests: `npm run test:golden` after a build.
- An agent session has no Screen Recording grant: `screencapture` fails; use `scripts/screenshot.mjs` (CDP, page
  content only; `--fake-recordkit` shows Screen Recording denied). Real capture, grants, native dialogs and real
  key presses are HUMAN. Drive the lifecycle with `APP_TEST_HOOKS=1 FLICAST_FAKE_RECORDKIT=1`.
- Never `pkill -f electron` (FliCut and Teletubby match; an Electron killed so orphans a busy `recordkit-rpc`).
  `spike/recordkit-probe.mjs` leaves an orphaned `recordkit-rpc`: `pgrep -fl recordkit-rpc` and kill that one.
- **`npm run app` runs the BUILT app as its own macOS app** (LaunchServices, `$FLICAST_HOME/launcher/FliCast.app`,
  bundle id `com.appydave.flicast.dev`), so FliCast owns its Screen Recording grant. The grant is keyed on that
  launcher: never delete or re-sign it casually. Raise a running FliCast with `app.sh show`, never
  `open -a node_modules/electron/dist/Electron.app` (that starts a bare Electron showing its default window). A
  non-default `FLICAST_HOME` gets its own bundle id, so a test's `stop`/`show` never reaches the person's app;
  `FLICAST_LAUNCH_HIDDEN=1` launches unseen. `npm run dev` (HMR) inherits its parent's grant.
- Another Electron may already hold the uat CDP ports (9333/9334): every story then reads an empty page and
  "__appTestHooks not reachable". Check with `lsof`, move the run with `UAT_RENDERER_PORT` / `UAT_MAIN_PORT` /
  `UAT_SERVICE_PORT`. Never kill the other app.
- Every uat or screenshot run opens a window: on a machine a person is using, batch them into one announced run.
- Windows reopen from `@flivideo/core`'s shared store. A run with its own `FLICAST_HOME` uses the `flicast/scratch*`
  keys (`src/main/window-keys.ts`); point `FLICAST_WINDOW_STATE` at a scratch file when a check must not move the
  person's saved spot. The uat harness restores position only (`FLICAST_WINDOW_RESTORE=position`).
- `*.log` is gitignored (uat evidence needs `git add -f`); stage explicit paths — `git add .` commits `.appynet/`.
- Generated, never hand-edited: the skill's verb list (`npm run skill:verbs`), `docs/spec/document-coverage.*`
  (`npm run audit:coverage`), `api/*` (`npm run api:all`). A new verb: build, then `skill:verbs` and `api:all`.

## Non-default conventions

- Every UI control carries `data-verb` (+ `data-path`) and words; drivers locate by verb. A bare `<button>` without
  `.btn` fails `test/renderer-interaction.test.ts`. Two controls can share a verb: prefer the one without `data-path`.
- A command result must not use the envelope's names (`changed inverse previous ids warnings dryRun created`): the
  core throws `internal`. Call an id list `segmentIds`, `slices`, `cut` …
- Never call a mutating store method in a handler body; put it in `effect()` (runs before the commit; a throw after
  the commit rolls back).
- `autosaveMs: 0` saves inside `commit`: a test gating `writeProject` while racing a command deadlocks; use `1`.
- `registerAccelerator: false` on transport menu items; the renderer's one keydown handler decides text-field focus,
  and there is deliberately no renderer Cmd-Z (the menu is the single trigger).
- **`recording.defaults` null means NOT CHOSEN** (`microphone: null` used to mean none). Send `"none"` for no
  microphone/camera, `displayId: "main"` for the main display; target, its source and system audio start unset. Rigs
  arming from defaults seed `CHOSEN_RECORDING_DEFAULTS`; the uat home seeds the same.
- **A take that starts a project needs a name** (`recording.arm { name }`); a uat story sets
  `setVerb: recording.arm ~ name ~ …` before pressing ● Record.
- A new document field needs `.default()` (old files parse), regenerated goldens (`UPDATE_GOLDEN=1`, read the diff),
  and a verb or an allow-list entry with a reason (`test/drivability/allow-list.ts`).
- `import 'pixi.js/unsafe-eval'` must be the first import in `src/compositor/index.ts` (strict CSP).

## Pitfalls

- `setVisibleOnAllWorkspaces(true)` makes the process a `UIElement` (no Dock, no Cmd-Tab) and `close()` does not
  undo it: unset it before closing the HUD, or the app "crashes" without crashing.
- A stale live `recordkit-rpc` can report `displays: []` while a fresh app sees the display; without the Screen
  Recording grant `[]` is the truth. A device list read during the helper's ~2 s warm-up is partial.
- `prepare()` can hang after `[InputRecorder] … failed to capture any rects`: bounded at 15 s, cause unpinned.
- Exported audio is ~44 ms late (AAC priming): pin click times to the first onset, not to zero.
- `app.getVersion()` in a dev build is Electron's; read `package.json` through `resolveAppRoot`, never `cwd()`.
- `node_modules/.bin/electron` is a Node wrapper; the app's pid is in `control.json`. SIGKILLing the wrapper leaves
  the app on the same inspector port. `app.quit()` from a CDP session waits for the websocket to close.
- Two Pixi Applications on one page share the texture pool; destroying one breaks the other.
- `project.create` adopts (moves) its bundle and answers `{ project: { id } }`; `projectId: undefined` silently reads
  the ACTIVE project, so a test on the wrong project can pass.
- The keystroke overlay hides plain typing unless `singleLetters` is on, joins labels with a NO-BREAK space, and
  draws a typing run as one press per word (`shown` counts words). Read `overlay.get` before blaming the compositor.
  SYSTEM.md § Non-obvious Constraints has the full rule.
- `app.on('activate')` must count editor windows only (the hidden render worker is a window too).
- The renderer imports core by path, never `@core/index` or `@flivideo/core` (it pulls `node:fs`): only the build
  fails. Hence `refusal-details.ts` restates `AppBusyDetails`.

## Decisions worth knowing

- Where a take is written is fixed at `recording.arm`: a name means a NEW project (a taken one is refused `exists`
  at arm); nothing is chosen on a person's behalf (`notChosen` lists every open choice).
- A cast rename that moves files is not an undo entry (undo would point at `cast/<a>/`): fresh undo stack.
- No git inside projects (ADR-0002); `audio.improve`'s `-improved.m4a` beside the mic take is the one derived file
  kept in a project.
- Door-2 resolution is hand-rolled because fli-core's `resolveOpenContext` refuses plain folders; drop it for
  `acceptFolders`.
- The RecordKit adapter is the one file an SDK upgrade touches; video-side own-window exclusion is
  `setContentProtection(true)` (`excludedProcessIDs` exists only on system audio).
- A refusal's `message` is neutral fact; retry facts go in typed `details` (ADR-0007). Codes are never renumbered.

## Scope limits

- Does NOT pause (no pause in RecordKit): "Stop & start a new scene" is the substitute.
- Does NOT copy / move / delete a cast project (`unsupported`); rename works. Packages can do all four.
