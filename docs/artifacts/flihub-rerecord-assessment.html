Placeholders & re-recording

What FliHub would need so you can drop a placeholder chapter in D07, keep recording, then come back and replace it, delete a segment and close the gap, or slot one in between. Nothing was built; this is the map.

The short answer

  • Today FliHub only goes forward. The inbox always offers the next number, nothing in the UI can change a segment number, and nothing closes a gap.
  • The real risk is FliCut and FliStudio. They find takes by filename. Renumber 06-2 to 06-1 and an existing edit quietly plays the wrong take.
  • My take: keep the number in the filename as the order you see, and only ever change it through one guarded FliHub action. Build "Replace this take" first. That alone is your D07 placeholder flow.

The core decision

Is a segment number a place, or a name tag?

OptionWhat it meansWhy it could winWhy it could hurt
A · PlaceThe number is the take's position; renumber files when things changeFinder, FliHub and the edit all show the same orderEvery renumber renames files, and the edit tools lose track
B · Name tagA number never changes once given; the order lives in a settings fileNo renames, everA lone 06-2 at the top forever; every app has to read the hidden order
C · Place, one guarded action ★A, but renumbering only happens through one FliHub action that checks, trashes, logs every move and can undoKeeps the filename as the order you read; the log lets FliCut and FliStudio followFull safety needs FliCut and FliStudio to read the log (phase 4)

My take: C. Your folder ruling says the recordings are the source of truth, named so the sequence shows. The "metadata over renames" rulings were about publishing and selects, not the take order. Renaming isn't the problem. Renaming without telling the neighbours is. FliCut already gives every clip a stable id, and its spec already plans a "find the moved file" relink.

Safety rules for any of this

Old takes always go to -trash, never overwritten. Every action is logged so undo works after a restart, and so trash can be restored. A renumber is checked before anything moves and refuses as a whole, with the reason shown, if a take is still transcribing or an edit uses it.

Phases 1 and 2 are the whole placeholder story for D07: no edit exists yet when you replace a placeholder, so the safety check rarely fires. Phases 3 and 4 are general reordering.

Two calls only you can make

1 · What is a segment?

A piece of the chapter (D01's edit uses all 20 takes in order), or a retake where the last one wins (how FliStudio labels "latest")? This assessment assumes piece, which means FliStudio's "latest" label is wrong for projects like D01.

2 · Which model?

Place, name tag, or place with one guarded action (recommended). Phase 1 works under any of them, so it can start once you've answered question 1.
